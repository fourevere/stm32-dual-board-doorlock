# 01. 시스템 구조와 인터페이스

BOARD_A는 인증과 도어 구동을, BOARD_B는 LCD 상태 표시와 IR 원격 입력을 담당합니다. 동일한 소스 묶음을 BOARD_A 또는 BOARD_B 매크로로 구분해 빌드합니다.

| 구간 | 입력 / 처리 / 출력 |
| --- | --- |
| BOARD_A | 키패드·RC522 → main.c의 인증 상태 처리 → 서보·LED·부저 |
| 보드 간 연결 | A의 USART6 ↔ B의 USART1 / RX 인터럽트 기반 패킷 조립 |
| BOARD_B | 수신 명령 → LCD 상태 표시 / IR 입력 → LOCK·UNLOCK 명령 송신 |
| 공통 기반 | 시작 코드·벡터 테이블·CMSIS 헤더·클록 설정·UART2 디버그 출력 |

| 장치 | 배선 / 주변장치 | 구현 파일 |
| --- | --- | --- |
| 키패드 4×4 | 행 PA0·PA1·PA4·PA8 / 열 PB3-PB6 EXTI | key.c, exception.c |
| RFID RC522 | SPI2 PB13-PB15 / SS PB2 / RST PB1 | rfid.c |
| 서보 | PB0 / TIM3 CH3 PWM | timer.c |
| 부저 | PA9 / TIM1 CH2 (BOARD_A) | timer.c |
| 보드 링크 | A PC6·PC7 / B PA9·PA10 | uart_link.c |
| LCD | PB8·PB9 / I2C1 / 주소 0x27 | lcd.c |
| IR 수신 | PC10 EXTI / TIM2 간격 측정 | ir.c, exception.c |
| 디버그 | PA2·PA3 / USART2 | uart.c |

> 핀 정보는 보존된 소스의 설정입니다. 최종 사진만으로 모든 신호의 전기적 연결을 검증한 것은 아닙니다. PA9는 서로 다른 보드의 부저·UART 기능에 각각 사용됩니다.

## 설계에서 드러나는 경험

주변장치별 드라이버 분리, 컴파일 옵션에 따른 보드 역할 분기, 인터럽트에서 이벤트를 받고 메인 루프에서 처리하는 구조, 바이트 스트림의 패킷 조립을 한 시스템으로 통합했습니다.

# 02. 기능과 상태 흐름

| 기능 | 소스에 존재하는 동작 | 제약 |
| --- | --- | --- |
| 일반 비밀번호 | 3자리 입력 후 # 확인, * 취소. 성공 시 서보 열림과 알림 후 닫힘 | 숫자 전용 필터가 없어 A-D도 입력 가능 |
| 사용자 RFID | 등록된 4바이트 UID 비교 후 도어 열림 | 고정 UID 목록이며 카드 암호 인증은 없음 |
| 관리자 모드 | 관리자 카드 → 새 비밀번호 입력 → 재입력 일치 시 변경 | 변경 값은 RAM에만 저장 |
| 오류 안내 | 실패 수 증가·LED 점멸·부저·LCD WRONG PW | 3회 후 카운터 초기화. 시간 잠금은 없음 |
| IR 원격 제어 | 32비트 수신값 중 정해진 두 코드를 잠금·해제로 연결 | 별도 명령 인증 없음 |
| 상태 표시 | 입력 길이, 인증 성공·실패, 관리자·변경 안내를 LCD에 표시 | 단일 수신 완료 플래그 사용 |

## 인증 상태 전이

ST_IDLE에서 일반 입력을 처리합니다. 관리자 카드가 확인되면 ST_ADMIN_NEW1에서 첫 비밀번호를 받고, ST_ADMIN_NEW2에서 재입력을 비교합니다. 일치하면 PASSWORD 배열을 갱신하고 대기로 돌아갑니다. 취소 입력도 대기 복귀로 연결됩니다.

## UART 프레임

STX(0x02) | CMD | LEN | DATA | XOR | ETX(0x03). XOR은 명령·길이·데이터 바이트를 대상으로 계산합니다. 수신 상태 머신은 구분자·명령·길이·본문·체크섬·종료 바이트를 순서대로 처리합니다.

| 명령 | 값 | 목적 |
| --- | --- | --- |
| ENTER / ADMIN | 0x01 / 0x02 | 카드 인증 결과 / 관리자 진입 |
| PWCHG / PW_OK / PW_FAIL | 0x03 / 0x04 / 0x05 | 비밀번호 변경·성공·실패 |
| PW_INPUT / IDLE | 0x06 / 0x07 | 입력 길이 / 대기 화면 |
| LOCK / UNLOCK | 0x10 / 0x11 | 원격 잠금 / 해제 |

> 서보 설정값은 20,000 tick 주기와 500-2,500 tick 펄스입니다. 1 MHz 타이머 설정을 의도하나, 본 작업에서는 오실로스코프 주기·각도·응답 시간을 측정하지 않았습니다.

# 03. 소스 점검에서 확인한 한계

아래 항목은 2026.09.12 정적 소스 점검 결과입니다. 당시 해결했다고 소급해서 적지 않으며, 공개 사본에도 역사적 동작을 유지했습니다.

| 항목 | 관찰 근거 | 다음 보완 방향 |

| 클록 기준 불일치 | Clock_Init / option.h는 96 MHz, 링크 BRR은 84 MHz, LCD I2C는 42 MHz 상수 사용 | PCLK 기준 계산 통일 후 실제 UART baud·I2C 주기 측정 |

| 비밀번호 취급 | RAM 저장, 변경 값을 UART·디버그 출력으로 전달 | 전송 최소화·로그 마스킹·비휘발성 저장 정책 |
| 인증 강도 | UID 비교, 3자리 입력, 인증 없는 원격 명령 | 실제 서비스 요구에 맞춘 인증·접근 제한 |
| 동시 이벤트 | 키 릴리스·도어 대기·일부 I/O가 busy-wait이며 수신 큐가 없음 | 논블로킹 상태 처리와 이벤트 큐 |
| 시연과 최종 파일 | main.c 수정 시각이 보관된 기존 ELF/BIN보다 늦음 | 소스와 당시 실행 바이너리의 동일성은 별도 증거 필요 |

## 보고서에서 확정하지 않은 수치

인증 성공률, 오류율, 연속 동작 횟수, 최악 응답 시간, 실제 baud, PWM 오차, 전력 소비는 측정 원자료가 없어 기재하지 않습니다. 컴파일 성공을 장치 동작 성공률로 바꾸지 않습니다.

## 공개 사본 처리

실제 초기 비밀번호와 두 카드 UID는 예제값으로 교체했습니다. 원본의 값은 보고서·README에 싣지 않았고, 해당 값이 보이는 터미널 사진과 시연 영상은 공개 묶음에서 제외했습니다.
